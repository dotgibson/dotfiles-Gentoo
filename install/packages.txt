# dotfiles-Gentoo/install/packages.txt
# Portage ATOMS (category/name) for the modern terminal stack. One per line.
# mise (not in the tree) and tree-sitter-cli (cargo) are handled by bootstrap.sh.
#
# Heads-up: several modern Rust CLIs are ~amd64 (testing-keyworded) on a stable
# profile, and two of them (app-shells/zoxide, sys-fs/duf) have NO stable ebuild at
# all. bootstrap.sh installs gentoo/package.accept_keywords for exactly those, so
# this list emerges cleanly on stable; --no-portage-config opts out, and
# gentoo/package.use.example stays a review-and-copy template (USE is your call).
# Building from source is slow — enable the binhost (--getbinpkg, see README).

# ── core-doctor extras that are NOT in the main tree ──────────────
# In the GURU overlay (bootstrap.sh enables GURU + emerges these best-effort).
# NOTE: the main-tree emerge above runs BEFORE GURU is enabled, so overlay-only
# atoms MUST live here, not in the blocks above — there they'd fail the pre-GURU
# emerge (a `skipped: <atom>` line) and never get retried:
#   sys-apps/sd  app-misc/glow  net-misc/xh
#   app-shells/carapace  app-misc/1password-cli (op)
#   app-misc/tealdeer  app-misc/yazi  dev-vcs/lazygit  app-shells/direnv
#   net-analyzer/gping
# Provided by mise (gentoo/mise-tools.toml), NOT emerged:
#   gum
#   Do NOT add app-misc/gum back: no such ebuild exists in ::gentoo OR in GURU,
#   so it can only ever emerge as a `skipped:` line — which reads like a keyword
#   mask and gets "fixed" with an accept_keywords entry that unmasks nothing.
#   That is exactly how it survived in the guru_install list; mise owns gum.
# Installed via `go install` (not packaged anywhere), handled in bootstrap.sh:
#   gron  sesh  shfmt
#   shfmt is absent from BOTH ::gentoo and GURU (PORTING-MATRIX footnote 7): there
#   is no dev-go/shfmt atom, and the third-party overlays that carry it call it
#   dev-util/shfmt. So it takes the go path, like gron and sesh.
# Built with cargo by bootstrap.sh (packaged nowhere on Gentoo):
#   tree-sitter-cli  viddy          — always; Core wires both
#   ouch  ast-grep  jnv  jj  watchexec  — the opt-in set, skipped by --no-extras
#   The jj crate is jj-cli, NOT jujutsu: the `jujutsu` crate name is an abandoned
#   stub (last published 0.7.2) whose description only redirects readers to jj-cli,
#   so `cargo install jujutsu` gets you the redirect, not the VCS. Likewise the
#   watchexec crate is `watchexec-cli` — note the -cli suffix; plain `watchexec` is
#   the library and installs no binary. core/PORTING-MATRIX.md footnotes 8 and 25 are canonical for both.
# Do NOT add dev-vcs/jujutsu or dev-go/shfmt — neither atom exists.
